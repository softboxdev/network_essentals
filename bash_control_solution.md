## ЗАДАНИЕ 2: `calculator.sh`
```bash
#!/bin/bash
read -p "Введите первое число: " a
read -p "Введите второе число: " b
read -p "Введите операцию (+, -, *, /): " op

if [ "$op" = "+" ]; then
    echo "Результат: $a + $b = $((a + b))"
elif [ "$op" = "-" ]; then
    echo "Результат: $a - $b = $((a - b))"
elif [ "$op" = "*" ]; then
    echo "Результат: $a * $b = $((a * b))"
elif [ "$op" = "/" ]; then
    echo "Результат: $a / $b = $((a / b))"
else
    echo "Неизвестная операция"
fi
```
```bash
#!/bin/bash
read -p "Введите первое число: " a
read -p "Введите второе число: " b
read -p "Введите операцию (+, -, *, /): " op

case "$op" in
    +) echo "Результат: $a + $b = $((a + b))" ;;
    -) echo "Результат: $a - $b = $((a - b))" ;;
```

## ЗАДАНИЕ 2: `calculator.sh`

```bash
#!/bin/bash
# Скрипт-калькулятор: выполняет арифметические операции над двумя числами

# Запрашиваем первое число
read -p "Введите первое число: " num1

# Проверка: является ли ввод числом
if ! [[ "$num1" =~ ^-?[0-9]+([.][0-9]+)?$ ]]; then
    echo "Ошибка: '$num1' не является числом!" >&2
    exit 1
fi

# Запрашиваем второе число
read -p "Введите второе число: " num2

if ! [[ "$num2" =~ ^-?[0-9]+([.][0-9]+)?$ ]]; then
    echo "Ошибка: '$num2' не является числом!" >&2
    exit 1
fi

# Запрашиваем операцию
read -p "Введите операцию (+, -, *, /): " op

# Выполняем операцию с помощью bc (для поддержки дробных чисел)
case "$op" in
    +)
        result=$(echo "$num1 + $num2" | bc)
        ;;
    -)
        result=$(echo "$num1 - $num2" | bc)
        ;;
    \*)
        result=$(echo "$num1 * $num2" | bc)
        ;;
    /)
        # Проверка деления на ноль
        if [ "$(echo "$num2 == 0" | bc)" -eq 1 ]; then
            echo "Ошибка: деление на ноль невозможно!" >&2
            exit 1
        fi
        result=$(echo "scale=4; $num1 / $num2" | bc)
        ;;
    *)
        echo "Ошибка: неизвестная операция '$op'. Допустимо: +, -, *, /" >&2
        exit 1
        ;;
esac

# Выводим результат
echo "Результат: $num1 $op $num2 = $result"
```

**Запуск:**
```bash
chmod +x calculator.sh
./calculator.sh
```

> 💡 Если `bc` не установлен: `sudo dnf install bc`

## ЗАДАНИЕ 4: `list_files.sh`

```bash
#!/bin/bash
# Скрипт вывода .txt файлов в директории с их размерами

# Проверка наличия аргумента
if [ $# -eq 0 ]; then
    echo "Ошибка: не указан путь к директории." >&2
    echo "Использование: $0 <путь_к_директории>" >&2
    exit 1
fi

dir="$1"

# Проверка существования директории
if [ ! -e "$dir" ]; then
    echo "Ошибка: директория '$dir' не существует!" >&2
    exit 1
fi

# Проверка, что это именно директория
if [ ! -d "$dir" ]; then
    echo "Ошибка: '$dir' не является директорией!" >&2
    exit 1
fi

# Выводим заголовок
echo "Найдены .txt файлы в $dir:"

# Флаг для отслеживания найденных файлов
found=0

# Перебираем .txt файлы в директории
for file in "$dir"/*.txt; do
    # Проверка: файл существует (защита от случая, когда нет .txt файлов)
    if [ -f "$file" ]; then
        size=$(du -h "$file" | cut -f1)
        echo "- $(basename "$file") ($size)"
        found=1
    fi
done

# Если ничего не найдено
if [ $found -eq 0 ]; then
    echo "  .txt файлы не найдены"
fi
```

**Запуск:**
```bash
chmod +x list_files.sh
./list_files.sh /home/user/documents
./list_files.sh /несуществующая/директория
```

```bash
#!/bin/bash
```

## 🔍 Разбор по строкам

### Строка 1: `#!/bin/bash`
**Шебанг (shebang)** — это специальная конструкция, которая указывает системе, какой интерпретатор использовать для выполнения скрипта.
- `#!` — магические символы, которые ядро Linux распознаёт в начале файла
- `/bin/bash` — путь к интерпретатору Bash
- **Без этой строки** система попытается выполнить скрипт текущей оболочкой, что может привести к непредсказуемому поведению
- **Важно:** шебанг должен быть первой строкой, без пробелов перед `#!`

### Строка 2: `# Скрипт приветствия...`
Комментарий. В Bash комментарии начинаются с `#` и игнорируются интерпретатором.
- Нужны для документирования кода (+2 балла по критериям)

### Строки 4-7: Проверка интерактивности
```bash
if [ ! -t 0 ]; then
    echo "Ошибка: скрипт требует интерактивного ввода" >&2
    exit 1
fi
```

**Разбор:**
- `if ...; then ... fi` — условный оператор Bash
- `[ ! -t 0 ]` — тестовая конструкция:
  - `[ ... ]` — команда `test` (синоним)
  - `-t 0` — проверяет, является ли файловый дескриптор `0` (stdin) **терминалом**
  - `!` — логическое отрицание
  - Итого: «если stdin **не** является терминалом»
- `echo "..." >&2` — вывод сообщения об ошибке:
  - `>&2` — перенаправление потока в **stderr** (поток ошибок, дескриптор 2)
  - Это правильно, потому что сообщения об ошибках должны идти в stderr, а не в stdout
- `exit 1` — завершение скрипта с **кодом возврата 1** (ненулевой код = ошибка)
  - `0` — успех, любое другое число — ошибка

**Зачем это нужно?** Если скрипт запустят через `echo "Иван" | ./greeting.sh`, то `read` не сможет корректно запросить ввод, и скрипт завершится с ошибкой вместо зависания.

### Строка 9: `read -p "Введите ваше ФИО_ГРУППА: " name`
**Команда `read`** — читает строку из stdin и сохраняет в переменную.
- `-p "..."` — опция **prompt**: выводит приглашение перед вводом
- `name` — имя переменной, куда сохранится введённое значение
- **Пробел после `-p "..."`** обязателен

**Важно:** переменные в Bash не требуют объявления типа. `name` создаётся автоматически.

### Строки 11-14: Проверка на пустой ввод
```bash
if [ -z "$name" ]; then
    echo "Ошибка: имя не может быть пустым!" >&2
    exit 1
fi
```

**Разбор:**
- `-z "$name"` — тест на **пустую строку** (zero length)
  - `-z` возвращает истину, если длина строки = 0
  - `"$name"` — **обязательно в кавычках!** Если имя содержит пробелы, без кавычек Bash разобьёт его на несколько аргументов, и тест сломается
- Альтернативный вариант: `[ ${#name} -eq 0 ]` — проверка длины через `${#name}`

**Правило хорошего тона:** Всегда заключайте переменные в двойные кавычки `"$var"`, если не уверены, что там нет пробелов.

### Строка 16: `echo "Привет, $name! Добро пожаловать в мир Bash!"`
- `$name` — **подстановка переменной**: Bash заменяет `$name` на её значение
- Внутри **двойных кавычек** подстановка работает
- Внутри **одинарных кавычек** (`'...'`) — не работает (вывелось бы буквально `$name`)

## 🔍 Разбор ключевых моментов

### Регулярное выражение для проверки числа
```bash
[[ "$num1" =~ ^-?[0-9]+([.][0-9]+)?$ ]]
```

**Разбор:**
- `[[ ... ]]` — **расширенная** тестовая конструкция (в отличие от `[ ... ]`):
  - Поддерживает регулярные выражения через `=~`
  - Не требует кавычек для переменных слева от `=~`
  - Работает быстрее и безопаснее
- `=~` — оператор сопоставления с регулярным выражением
- Регулярка `^-?[0-9]+([.][0-9]+)?$`:
  - `^` — начало строки
  - `-?` — необязательный минус (ноль или один раз)
  - `[0-9]+` — одна или более цифр
  - `([.][0-9]+)?` — необязательная группа: точка + цифры
  - `$` — конец строки
- **Что пропускает:** `10`, `-5`, `3.14`, `-0.5`
- **Что отвергает:** `abc`, `12abc`, `1.2.3`, пустая строка

**Почему `.` в `[.]`?** Точка в регулярках — спецсимвол (любой символ). Чтобы сделать её буквальной, её помещают в квадратные скобки или экранируют `\.`.

### Конструкция `case`

```bash
case "$op" in
    +) ... ;;
    -) ... ;;
    \*) ... ;;
    /) ... ;;
    *) ... ;;
esac
```

- `case` — аналог `switch` в других языках
- `"$op"` — проверяемое значение (в кавычках — хорошая практика)
- Каждый шаблон заканчивается `)` и `;;`
- `\*` — **экранирование**: `*` в `case` — спецсимвол (любое значение), поэтому его нужно экранировать обратным слешем
- `*)` — шаблон по умолчанию (default), срабатывает, если ничего не подошло

### Команда `bc` (Basic Calculator)

```bash
result=$(echo "$num1 + $num2" | bc)
```

**Разбор:**
- `bc` — консольный калькулятор, поддерживает **дробные числа** (в отличие от `$(( ))`, который работает только с целыми)
- `echo "10 + 5" | bc` — передаём выражение через pipe в `bc`, получаем `15`
- `$(...)` — **command substitution**: подставляет вывод команды в переменную
- **Почему не `$((num1 + num2))`?** Потому что арифметика Bash работает только с **целыми числами**: `$((10/3))` = `3`, а не `3.333`

**Опция `scale=4`:**
```bash
result=$(echo "scale=4; $num1 / $num2" | bc)
```
- `scale=4` — задаёт **4 знака после запятой** для операций деления
- Без этой опции `bc` при делении вернёт только целую часть
- Пример: `echo "10/3" | bc` → `3`, а `echo "scale=4; 10/3" | bc` → `3.3333`

### Проверка деления на ноль

```bash
if [ "$(echo "$num2 == 0" | bc)" -eq 1 ]; then
    echo "Ошибка: деление на ноль невозможно!" >&2
    exit 1
fi
```

**Разбор:**
- `echo "$num2 == 0" | bc` — `bc` возвращает `1` (истина) или `0` (ложь)
- `$(...)` — получаем результат
- `[ "..." -eq 1 ]` — сравнение с 1
- `-eq` — **числовое** сравнение (equals)
- Альтернатива: `[ "$num2" = "0" ]` — но не сработает для `0.0`

**Важно:** Мы не можем просто написать `[ "$num2" -eq 0 ]`, потому что `-eq` работает только с целыми числами и упадёт на `0.0`. Поэтому используем `bc`.

## 🔍 Разбор ключевых моментов

### Специальные переменные Bash

| Переменная | Значение |
|-----------|----------|
| `$0` | Имя скрипта (например, `./check_number.sh`) |
| `$1`, `$2`, ... | Первый, второй и т.д. аргументы командной строки |
| `$#` | Количество переданных аргументов |
| `$@` | Все аргументы как отдельные строки |
| `$*` | Все аргументы одной строкой |
| `$?` | Код возврата последней команды |

### Проверка количества аргументов

```bash
if [ $# -eq 0 ]; then
```

- `$#` — число аргументов
- `-eq 0` — равно нулю
- Если пользователь запустил `./check_number.sh` без числа, `$#` = 0

**Почему не `[ -z "$1" ]`?** Потому что при отсутствии аргумента `$1` пустой, но `-z` менее надёжен. Проверка `$#` — стандартный способ.

### Регулярка для целого числа

```bash
[[ "$1" =~ ^-?[0-9]+$ ]]
```

- `^-?[0-9]+$` — опциональный минус + одна или более цифр
- **Не пропускает** дробные числа (для задания нужны только целые)

### Цепочка `if / elif / else`

```bash
if [ "$num" -gt 0 ]; then
    echo "Число $num является положительным"
elif [ "$num" -lt 0 ]; then
    echo "Число $num является отрицательным"
else
    echo "Число $num является нулём"
fi
```

**Операторы числового сравнения:**

| Оператор | Значение |
|----------|----------|
| `-eq` | равно |
| `-ne` | не равно |
| `-gt` | больше (greater than) |
| `-ge` | больше или равно |
| `-lt` | меньше (less than) |
| `-le` | меньше или равно |

**Почему не `>` и `<`?** Внутри `[ ]` символы `>` и `<` используются для **перенаправления ввода-вывода**, а не для сравнения. Поэтому для чисел используют `-gt`, `-lt`.

**Логика ветвления:**
1. Если `num > 0` → положительное (остальные ветки пропускаются)
2. Иначе если `num < 0` → отрицательное
3. Иначе (единственный оставшийся вариант) → ноль

# ЗАДАНИЕ 4: `list_files.sh`

```bash
#!/bin/bash
# Скрипт вывода .txt файлов в директории с их размерами

if [ $# -eq 0 ]; then
    echo "Ошибка: не указан путь к директории." >&2
    echo "Использование: $0 <путь_к_директории>" >&2
    exit 1
fi

dir="$1"

if [ ! -e "$dir" ]; then
    echo "Ошибка: директория '$dir' не существует!" >&2
    exit 1
fi

if [ ! -d "$dir" ]; then
    echo "Ошибка: '$dir' не является директорией!" >&2
    exit 1
fi

echo "Найдены .txt файлы в $dir:"

found=0

for file in "$dir"/*.txt; do
    if [ -f "$file" ]; then
        size=$(du -h "$file" | cut -f1)
        echo "- $(basename "$file") ($size)"
        found=1
    fi
done

if [ $found -eq 0 ]; then
    echo "  .txt файлы не найдены"
fi
```

## 🔍 Разбор ключевых моментов

### Операторы проверки файлов

| Оператор | Значение |
|----------|----------|
| `-e file` | файл **существует** (exist) |
| `-f file` | существует и является **обычным файлом** |
| `-d file` | существует и является **директорией** |
| `-r file` | доступен для **чтения** |
| `-w file` | доступен для **записи** |
| `-x file` | **исполняемый** |
| `-s file` | существует и **не пустой** |

### Проверки существования и типа

```bash
if [ ! -e "$dir" ]; then   # директория вообще существует?
if [ ! -d "$dir" ]; then   # это директория, а не файл?
```

Две проверки разделены, потому что сообщения об ошибках разные:
- Первая: «путь не существует»
- Вторая: «путь существует, но это файл, а не директория»

### Цикл `for`

```bash
for file in "$dir"/*.txt; do
    ...
done
```

**Разбор:**
- `*.txt` — **glob-шаблон** (wildcard): Bash раскрывает его в список файлов
- `"$dir"/*.txt` — сначала подставляется `$dir`, потом раскрывается `*`
- **Важно:** кавычки вокруг `$dir`, но **НЕ** вокруг `*.txt` — иначе Bash не раскроет шаблон

**Подводный камень:** Если в директории нет `.txt` файлов, `"$dir"/*.txt` не раскроется и останется буквально как `"/path/*.txt"`. Тогда проверка `[ -f "$file" ]` защитит от ложного вывода.

### Защита от несуществующих файлов

```bash
if [ -f "$file" ]; then
```

- `-f` проверяет, что это **обычный файл** (не директория, не битая ссылка)
- Если `*.txt` не раскрылся, `$file` = `/path/*.txt`, и тест вернёт ложь → итерация пропускается

### Получение размера файла

```bash
size=$(du -h "$file" | cut -f1)
```

**Разбор:**
- `du -h "$file"` — вывод: `4.0K    /path/file.txt`
  - `-h` — human-readable (K, M, G вместо байт)
- `| cut -f1` — берём **первое поле** (размер), разделитель по умолчанию — табуляция
- `$(...)` — сохраняем в переменную

**Альтернативы:**
- `ls -lh "$file" | awk '{print $5}'` — тоже работает
- `stat -c%s "$file"` — размер в байтах (без K/M/G)

### Флаг `found` для отслеживания результатов

```bash
found=0
...
    found=1
...
if [ $found -eq 0 ]; then
    echo "  .txt файлы не найдены"
fi
```

**Зачем?** Если в директории **нет** `.txt` файлов, цикл не выполнится ни разу, и пользователь не поймёт: то ли файлов нет, то ли скрипт сломался. Флаг решает эту проблему.

### `basename` — получение имени файла

```bash
echo "- $(basename "$file") ($size)"
```

- `basename /home/user/file.txt` → `file.txt`
- Убирает путь, оставляя только имя
- Альтернатива в Bash: `${file##*/}` — удаляет всё до последнего `/`

### Форматирование вывода

```bash
echo "- $(basename "$file") ($size)"
```

Результат:
```
- file1.txt (1.2K)
- notes.txt (4.5K)
```

Соблюдение единого стиля (`- имя (размер)`) — это **+1 балл** за аккуратное оформление.

# 🎓 Сводка ключевых концепций

## Условные операторы Bash

| Синтаксис | Когда использовать |
|-----------|-------------------|
| `[ ... ]` | Простые проверки (POSIX-совместимо) |
| `[[ ... ]]` | Регулярки, `&&`, `\|\|` внутри, безопаснее |
| `(( ... ))` | Арифметика с целыми числами |

## Кавычки в Bash

| Синтаксис | Поведение |
|-----------|-----------|
| `"$var"` | Подстановка переменной, защита от разбиения |
| `'$var'` | Буквальная строка, без подстановки |
| `$var` | Подстановка **без** защиты (опасно с пробелами) |
| `"$@"` | Все аргументы как отдельные строки (правильно) |
| `"$*"` | Все аргументы одной строкой |

## Коды возврата

| Код | Значение |
|-----|----------|
| `0` | Успех |
| `1` | Общая ошибка |
| `2` | Неправильное использование |
| `126` | Нет прав на выполнение |
| `127` | Команда не найдена |
| `130` | Прерывание Ctrl+C |

## Потоки ввода-вывода

| Дескриптор | Поток | Перенаправление |
|-----------|-------|-----------------|
| `0` | stdin | `< file` |
| `1` | stdout | `> file`, `>> file` |
| `2` | stderr | `2> file`, `>&2` |
